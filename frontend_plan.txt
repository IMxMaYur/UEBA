Extend the AI Insider Threat Detection System by implementing a **User Behavioral Baseline Engine**.

This module learns the **normal behavioral patterns of each employee** and detects deviations that may indicate insider threats.

The system processes activity logs from the CERT Insider Threat Dataset v4.2 including:

* logon events
* file access logs
* USB device usage
* web browsing activity
* email activity
* user metadata (department, role)

---

OBJECTIVE

Build a behavioral analytics engine that establishes **baseline activity profiles for every user** and continuously compares new activities against those baselines.

The engine should generate **behavioral anomaly scores** used by the risk scoring system and security dashboard.

BASELINE MODEL

For each user, compute a **behavioral baseline profile**.

Example baseline structure:

UserBaselineProfile

* user_id
* avg_login_hour
* login_hour_variance
* avg_files_accessed_daily
* avg_usb_usage_frequency
* common_domains
* avg_email_count
* department_norm_comparison

The baseline should update periodically using historical logs.

---

BEHAVIOR DEVIATION DETECTION

When new activity occurs, compare it against the user's baseline.

Compute deviations such as:

* login outside normal hours
* excessive file access
* abnormal USB transfers
* unusual web domains
* abnormal email activity

Calculate a **behavioral anomaly score** between 0 and 1.

Example logic:

deviation_score = weighted_sum(
login_deviation,
file_access_deviation,
usb_deviation,
web_activity_deviation,
email_deviation
)

---

Possible models:

* Isolation Forest
* Autoencoder
* Local Outlier Factor
* Statistical Z-score detection

The system should combine **statistical baseline deviations with ML anomaly detection**.

Extend the AI Insider Threat Detection System with an **Attack Pattern Correlation Engine** capable of detecting **multi-event insider threat scenarios**.

The system must analyze activity logs from the CERT Insider Threat Dataset v4.2 and correlate sequences of suspicious events across multiple sources.

Log sources include:

* logon activity
* file access logs
* USB device activity
* web browsing logs
* email communication logs

---

OBJECTIVE

Traditional anomaly detection detects **single unusual events**.

The Attack Pattern Correlation Engine should detect **chains of events that together indicate a malicious insider attack**.

Example:

Login → Sensitive file access → USB copy → Cloud upload

Even if each event alone is not highly anomalous, the **sequence of events may indicate data exfiltration**.

The engine should detect such sequences and generate **high-confidence threat alerts**.

---

ATTACK PATTERN LIBRARY

Define a library of insider threat patterns.

Each pattern consists of a **sequence of events within a time window**.

Example patterns:

Data Exfiltration Pattern

1. login
2. access sensitive files
3. copy files to USB
4. visit cloud storage site

Credential Misuse Pattern

1. login from unusual time
2. login from new device
3. access privileged resources

Disgruntled Employee Pattern

1. excessive file downloads
2. job search website visits
3. email communication with external domains

Privilege Abuse Pattern

1. access admin resources
2. modify sensitive files
3. large data transfer
